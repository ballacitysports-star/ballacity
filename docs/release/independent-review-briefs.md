# Independent review briefs (Codex)

**Why this file exists.** The release plan asks for focused independent reviews by Codex of five areas. Codex is not available inside the Claude Code session that prepared these changes (no Codex tool or connector is installed, and installing a third-party plugin that sends repository content to another vendor needs the owner's decision). Fresh-context Claude reviewers were run instead and their findings are in `docs/release/independent-review-results.md`; **they are not a substitute for Codex**. The briefs below are ready to hand to Codex unchanged. Codex should review the final heads recorded in the results file, read-only, and report file-and-line findings with severity, a demonstrated failure scenario where possible, and a suggested remediation. Claude Code then corrects confirmed issues and Codex reviews the corrected heads.

Common rules for every brief: read-only; no production system, credential or secret; no GitHub or hosting writes; Postgres 16 locally with `node scripts/db-test.mjs --keep --db <your_db>` then a temporary test under `supabase/tests` run with `--reuse --db <your_db> --only <name>`; helpers in `supabase/tests/support/helpers.sql`; delete temporary files and drop databases afterwards. Report format: Severity (Critical/High/Medium/Low/Info), `file:line`, one-sentence defect, demonstrated failure scenario (command and result) or "not demonstrated" with reasoning, concrete fix and its compatibility cost; then what was verified as sound.

## 1. Messaging authorization (PR #270, stacked on #265)

Policy: unlinked 16-17 year olds cannot receive unsolicited adult messages; unrelated minors cannot start conversations without an authorized context; a guardian's "peers" setting never authorizes an adult; a shared public game does not authorize messaging a 13-15 year old; a minor contacting an adult through a post goes through a guardian-approved request; unknown age fails closed. Authorized contexts: verified guardian and child, same team, game host and confirmed participant, organization admin and member, an accepted guardian-approved request while the guardian link is active.
Read: `supabase/migrations/20261106140000_minor_messaging_authorization.sql`, `20261106100000_minor_availability_privacy.sql`, tests 120, 200, 420, 430, 460, `src/lib/minor-messaging.ts`, `src/components/youth/GuardianContactApprovals.tsx`, `src/lib/notifications.functions.ts`, `src/lib/push.functions.ts`.
Try to break: any path creating a conversation, message, notification, push or request visible to a minor without authorization; mass assignment of `guardian_approved_*` or `status`; a guardian approving another family's request; recipient reading awaiting rows; TOCTOU; grants and `search_path` of every new definer function; null cohort; revocation inside existing conversations; history readability.

## 2. RLS and minor identity (PRs #263 and #266, integration branch)

Question: can an unrelated account (adult, teen, under-13, anonymous) use a minor host's `host_id` to recover or correlate identity or attributes through any table, RPC, Realtime channel, search, notification, storage or cache? Enumerate every readable table with a user-id column or FK to profiles/auth.users, every callable function taking or returning a user id, the Realtime publication, storage and views; re-test with realistic fixtures (approved posts, completed reels, comments, follows, team ownership, reviews, skill votes, RSVPs, memberships, waivers, payments). Distinguish exploitable today from only once minor hosting is activated.
Read: `20261105140000_minor_host_identity.sql`, `20261106110000_minor_host_correlation.sql`, `20261104120000_minor_host_payments_and_identity.sql`, tests 400 and 410, `docs/privacy/r1-minor-host-identifier.md`.

## 3. Image Storage policies and promotion (PRs #258 and #268)

Goal: no unprocessed original is ever publicly accessible: private staging, server-side metadata removal, scan before promotion, fail closed, cleanup, legacy-client transition. Try path confusion, overwrite of another user's object, TOCTOU between validation and publish, metadata the stripper misses (JPEG APPn/COM/MPF, PNG eXIf/iTXt/tEXt/zTXt/tIME, WebP EXIF/XMP/ICCP, trailing data), decompression bombs, authorization on promotion and sweep, every error path, and every storage write policy that stays open after the documented phase 2.
Read: `20261106120000_private_image_staging.sql`, `src/lib/image-promotion.server.ts`, `image-upload.ts`, `image-uploads.functions.ts`, `image-metadata.ts`, `image-metadata.server.ts`, `superadmin-image-metadata.functions.ts`, `message-attachments.functions.ts`, all `storage.objects` policies, tests 130 and 440, `docs/privacy/g3b-image-staging.md`.

## 4. Payment and guardian access dependencies (integration branch)

Do the privacy and messaging changes break or open a hole in payment and guardian-access paths? Check `can_notify` for legitimate payment, join and guardian notifications (minor payer, guardian payment manager, minor host) and for anything now more permissive; guardian access completeness and revoked-guardian exposure; minor-host payment handle visibility (`game_payee`, `get_host_payment_methods`, `payment_submissions`, `join_requests`, `paypal_orders` policies) including through the R1 correlation paths; later migrations that redefine an earlier protection.
Read: migrations 20261103* to 20261106*, tests 330, 335, 340, 345, 350, 360, 410, 420, 450, 460.

## 5. Migration and rollback safety (integration branch)

Check the documented order and dependencies (runbook sections 2 and 16), out-of-order and partial application, other PR merge orders, redefinitions that overwrite newer protection, idempotence and re-run, locks and long statements on hot tables, destructive statements and backfills against production-shaped data, the real recovery for each migration, that no recovery step can restore exact locations into public columns, app/database compatibility both ways, and definer-function hygiene (search_path, schema-qualified references, grants, the anonymous-callable allowlist in `00_schema_invariants.test.sql`).
