## Not closed

Recorded in the migration header and in the plan.

- **No backfill.** Removals made before this migration left no record, so those players can still rejoin an open game.
- **Remove and block writes no record.** After an unblock, the player can rejoin an open game.
- **A removed player keeps a verified payment and has no place.** The host refunds by hand, or invites the player back or
  approves their request.
- **Deleting a request resets the ask limits.** A removed player can delete their own request and ask again, starting at
  attempt 1 with no cooldown. Limiting asks is an owner decision.
- **About 22 other realtime channels** still re-read on SUBSCRIBED without `wait`, or do not catch up at all (#478's
  follow-up).
- **Paid-game over-approval by invitations** is still open from batch 29. The owner wants it fixed before the pilot has paid
  games.

## Rollback

`docs/rollbacks/20261202100000_removal_sticks.down.sql`, with `SET app.confirm_removal_sticks_rollback = 'yes'`. Through the
Management API, use `SET LOCAL` right after its `BEGIN`.

- **When it refuses:** if any function, trigger, read rule, owner or grant changed since the apply, or if another function's
  source names `game_removals`.
- **What it restores:** the six replaced definitions, verbatim.
- **What it drops:** the two triggers that close the older holes (the roster identity lock and the claim reopen block), the
  lift trigger, their functions, and the table with every record in it.
- **Order:** roll it back before the rollbacks of `20261119200000`, `20261125100000` and `20261129130000`, which pin the
  replaced definitions. Do not run the `20261103140000` rollback while this migration is applied: it has no definition guard.
- **Ledger row:** the rollback leaves it. Delete it by hand
  (`DELETE FROM supabase_migrations.schema_migrations WHERE version = '20261202100000'`).
- **The app** needs no rollback: it reads a missing table as "not removed".
