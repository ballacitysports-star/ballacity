## Route

- **Apply.** Each migration was applied through Lovable's database tool as one transaction. That transaction:
  1. inserts the `supabase_migrations.schema_migrations` row holding the file's text exactly as on `main`;
  2. refuses unless that text's md5 equals the file's;
  3. runs the stored text with `EXECUTE`.

  So the SQL that ran is byte for byte the SQL recorded. The route was tested locally first, including a wrong-md5
  control that rolls everything back.

- **Pre-check.** Production's whole-catalog fingerprint had to equal a local replay of the expected state. The
  fingerprint is an md5 over `docs/migration-evidence/catalog-fingerprint-cte.sql`, which covers functions, tables,
  columns, constraints, indexes, triggers, policies, buckets and publications.
- **Post-check.** The fingerprint had to equal a local replay that includes the migration.
