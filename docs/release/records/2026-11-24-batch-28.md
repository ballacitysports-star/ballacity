## Not closed (recorded in the migration header and the plan)

- A removed player can still join an open game (no approval required) again directly: the join gate never reads the
  request there.
- No one-off: requests left approved by removals made before this migration stay approved, and invitations already
  pending under a request declined before it are still guarded only by WP 5.5's taken-back rule (production had 0
  pending invitations at apply).
- A removal at the same moment as `release_expired_payment_holds` or `guardian_cancel_child_game` for the same player can
  deadlock; Postgres ends one of the two, nothing half-done is kept, and the app retries a removal once.

## Rollback

`docs/rollbacks/20261129130000_host_removal_and_decline_end_invites.down.sql`, with
`SET app.confirm_host_removal_rollback = 'yes'` (via the Management API, `SET LOCAL` right after its `BEGIN`). It
refuses if the function, the trigger or their grants changed since, and drops them. Requests it declined and
invitations it cancelled stay as they are. It leaves the ledger row; delete it by hand
(`DELETE FROM supabase_migrations.schema_migrations WHERE version = '20261129130000'`). The app needs no rollback (it
falls back when the function is missing).
