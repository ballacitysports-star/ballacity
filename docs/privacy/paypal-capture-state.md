## Retries never act twice (PayPal-Request-Id)

PayPal returns the first result for a repeated request that carries the same `PayPal-Request-Id`, for as long as it
keeps the id (see PayPal's API reference for each call).

| Call                         | Request id                                            | Effect                                                                                                                                                           |
| ---------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create order                 | `create-<random uuid>`, new for each checkout attempt | A resend after a lost answer returns the same order. A new attempt (the player presses the button again) makes a new order; one nobody approves charges nothing. |
| Capture (`captureRequestId`) | `capture-<order id>`                                  | The same on every attempt for an order, so an order is captured at most once, including a later retry of an order released back to `created`.                    |
| Refund (`refundRequestId`)   | `refund-<capture id>`                                 | A capture is refunded at most once.                                                                                                                              |

`postIdempotent` sends each of these once more with the same id when no answer came back at all (the connection
failed). An answer PayPal did give, success or error, is used as it is and never resent. Order lookups (`getOrder`,
`getOrderCapture`) are reads and carry no id.

## Reading a capture

`parseCaptureResponse` reads the capture itself, never the order: its id, status, amount, currency, PayPal's reason
(`status_details.reason`) and payee (the capture's, else its purchase unit's). It counts captures across all purchase
units; only exactly one is ever used. The checkout records a payment only for a capture whose own status is
`COMPLETED` that matches the amount, currency and payee (the payee confirmed before the capture is used when the
answer omits it). When the capture call gives no usable answer, `getOrderCapture` reads the order's capture from PayPal
the same way, so the amount checked is the captured amount, not the order's.
