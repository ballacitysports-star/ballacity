# R7: messaging policy audit (stranger-to-minor direct messaging)

Status: audit (merged, #267) plus the **implementation of the approved policy (migration `20261106140000_minor_messaging_authorization.sql`): implemented locally, open in a pull request. Not merged, not applied to production, not verified in production.**

Intended policy (owner, 2026-11-04): keep guardian-mediated messaging for minors; adult-to-adult communication continues with block, report and privacy controls; **no stranger-to-minor direct messaging**.

## Exceptions to the intended policy (existing behaviour, recorded in test 430 as "KNOWN EXCEPTION")

- **E1. Unlinked 16-17.** A 16-17 year old with no guardian link has no `child_controls` row, and `minor_messaging_block` has no rule for adult-to-16/17, so any adult can open a conversation. (A linked child defaults to guardian-only, so this affects self-registered teens only.)
- **E2. Minor to minor.** Two unrelated unlinked minors aged 16-17 can open a conversation; no rule covers minor-to-minor.
- **E3. "Peers" setting.** When a guardian chooses `peers`, an adult stranger can message a 16-17 year old. Test 120 asserts this as intended; under the stated policy it is an exception the owner should confirm.
- **E4. Shared-game context.** For 13-15 year olds (and under-13 when `child_adult_dm_requires_guardian_link` is turned off) the rule is "shares a game or chat", and any adult who has joined the same public game qualifies. Whether that is a "stranger" is a policy decision.
- **E5. Contact requests by a minor.** A 16-17 year old with no guardian controls can send a contact request to an adult through the adult's post (R2 keeps this; a request to a minor is the thing that is now gated).

## Implemented policy (owner approval 2026-11-04): exceptions E1 to E5 closed

One backend decision, `public.minor_messaging_block`, is used for conversation creation, for every message (so revocation, control changes and new rules apply inside existing conversations), and, through the same controls and contexts, for contact requests. `public.can_notify`, the gate for every server-written notification and push, applies the same test whenever a minor is involved. Unknown age counts as a minor; missing authorization means refused.

Authorized contexts (anything else is refused): a verified guardian and their child; two members of one team (players, coaches, managers); a game's host and a confirmed participant who joined for themselves; an accepted contact request that a verified guardian approved, re-verified at every use. **Not** a context: an organization administrator and a member (review finding: any adult can create an organization and add any user to it without consent; it returns when membership is consent-based). Shared chat history and a shared public game are **not** contexts. Two teens of the same age band (13-15 with 13-15, 16-17 with 16-17) may also talk when both guardians chose "peers" **and** they share a confirmed game; "peers" never involves an adult, an under-13 or an unknown age. Guardian controls (off, guardian only, teammates), blocks and the recipient's privacy settings apply first, as before.

| Exception                                          | Now                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1 unlinked 16-17 messaged by an adult             | refused with `needs_guardian_link`; the app tells the child to ask a parent or guardian to link the account, and tells the adult the player cannot be messaged yet                                                                                                                                             |
| E2 unrelated minors                                | refused unless a context above exists                                                                                                                                                                                                                                                                          |
| E3 guardian "peers" authorizes an adult            | never; peers can only authorize two minors with a confirmed shared game                                                                                                                                                                                                                                        |
| E4 shared public game authorizes messaging a 13-15 | no; a host and a confirmed participant is a context, two co-participants are not                                                                                                                                                                                                                               |
| E5 a minor contacts an adult through a post        | needs a linked guardian; the request is created as `awaiting_guardian`, invisible to the recipient, no notification to them, until a verified guardian approves it on the Guardian dashboard (declining withdraws it). Only after the recipient accepts does the request count as a context for a conversation |

Notifications: a person who is not authorized cannot place a notification or push in a minor's inbox (previously any game-mate or contact-request party could). Blocks stop notifications. Guardians are notified when their child's request is waiting.

Revocation: removing a guardian link, removing someone from a team, or changing the controls takes effect at the next message; history stays readable by both participants. The `age_policy` flags `child_adult_dm_requires_guardian_link` and `teen_adult_dm_requires_shared_context` can no longer loosen adult-to-minor messaging (the backend floor does not depend on them); the admin panel text should say so.

Compatibility and expected product effect: self-registered 16-17 year olds without a guardian link lose adult messaging until a guardian is linked; existing conversations that no longer have an authorized context stop accepting new messages and remain readable; older apps see the generic safety-settings message for the new reason codes. Recovery is forward only; relaxing the policy needs an owner-approved migration.

Not covered by tests: the organization-administrator context (verified by reading the helper only; add a fixture in the sandbox, ST-7.6). Guardian approval is a dashboard card, not a push to the guardian's phone beyond the existing in-app notification.

## Final owner decisions applied (2026-11-05)

- A shared public game alone never authorizes direct messaging: the shared-game "peers" context is removed.
- Teen-to-teen messaging needs a verified context (same team) or mutual consent: a request from a teen to a teen of the same age band whose guardian allows peers, approved by the sender's verified guardian and accepted by the recipient. The recipient's guardian can narrow it later at any time.
- An organizer context needs an **adult** host and a participant whose participation a verified guardian approved; a stranger cannot create it by publishing a public game, and a minor host is never reachable through it.
- Unlinked minors receive no unsolicited adult messages; guardian revocation applies to existing conversations; unknown ages fail closed; under-13 stays guardian-mediated; team and guardian communication keep working.

Test 460 now has 107 assertions.

What users will notice: a coach or teammate who was added to a roster directly (not through an invitation) can no longer message the team's minors, and a minor who joined a team without guardian approval (no linked guardian) cannot be messaged through that team; teams created by minors give their owner no messaging context. Hosts can no longer message or notify a minor whose join request the host has not approved, or more than 30 days after the game. Notifications and pushes that one user sends to a minor or unknown-age person arrive with fixed wording ("New message", "Game update") instead of the sender's text. A second parent or guardian added by family invitation waits for the current guardian's approval; adults cannot redeem family invitations. A manager can no longer add a person of unknown age directly.

Audit of the other `is_minor` gates the reviewer named (unknown age counts as "not a minor" there): `team_respond_invite` (an unknown-age invitee with a guardian link can accept without guardian approval) and `enforce_child_game_participation` / `child_game_participation_allowed` (an unknown-age participant is treated as not needing guardian approval to play). None of them is messaging-relevant any more, because messaging now requires a guardian-approved invitation or join request for every non-adult, unknown age included; they are left unchanged here and listed for the participation owners. Unknown-age accounts also cannot create join requests themselves (`AGE_VERIFICATION_REQUIRED`).

Test 460 now has 168 assertions; tests 120, 200 and 420 now give their minors guardian-approved memberships (`t.invited_member`, new in `supabase/tests/support/helpers.sql`).
